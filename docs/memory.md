# Willow 长期记忆

Willow 在每次 Agent 请求开始时读取两个 Markdown 文件：

- 全局：`~/.willow/memory/MEMORY.md`，保存跨项目偏好、工作方式和稳定环境信息。
- 项目：`<workspace>/.willow/memory/MEMORY.md`，保存项目约定、架构决策和长期限制。

当前用户指令和会话上下文优先于记忆；项目记忆优先于全局记忆。普通请求不额外调用模型总结。
本版沿用既有 compact，不增加退出记忆提取。

## Agent 写入

Agent 通过 `memory_update` 立即保存值得在未来会话使用的信息。只应保存稳定事实、明确纠正和偏好，
不保存任务进度、调试日志、TODO、推测、聊天摘要、凭据或容易从源码重新读取的信息。

```ts
memory_update({
  scope: "project",
  section: "Conventions",
  newText: "- This project uses pnpm.",
});
```

未提供 `oldText` 时追加到指定章节，章节不存在则创建；已有完全相同的文本不会重复添加。
纠正时提供 `oldText` 和 `newText`，只允许在指定章节内唯一精确匹配；空 `newText` 可以删除旧条目。
替换失败不会转为追加。更新不能引入新的章节边界；未闭合代码块和重复章节需要通过设置页或外部编辑修复。

一个 `## Section` 是一个记忆章节；`###` 和围栏代码块内的标题属于正文。
读取不会创建文件。首次 Agent 更新或显式原生打开时才创建默认文件；设置页仅点击保存才创建文件，避免启动污染工作区。
每个文件默认最大 16 KiB；超限拒绝写入，超限文件不注入 prompt，可通过替换精简或设置页编辑修复。

## 配置与 Core 接入

可以手动添加全局或项目 `.willow/memory/config.json`：

```json
{
  "enabled": true,
  "maxGlobalMemoryBytes": 16384,
  "maxProjectMemoryBytes": 16384
}
```

缺省值如上。容量必须为正安全整数，项目配置覆盖全局容量等设置；全局 enabled=false 为总开关，项目不能重新开启。
未知配置字段不生效。全局配置损坏停用两个 scope；项目配置损坏停用项目 scope，返回诊断。
设置页仍可查看文件并用原生应用修复。配置文件不会自动创建。

Core 的 `AgentCoreOptions.projectTrusted` 默认关闭；只有显式开启才读取项目记忆和配置、允许项目更新。
Work 对用户已添加的工作区开启此选项。全局路径始终基于用户 home，不随 `agentDir` 改变。
Core 导出 `readMemory`、`updateMemory`、`saveMemory`、`ensureMemoryFile` 和 Markdown/配置类型及辅助接口。
Plan 模式只读取记忆，不注册写工具；停用记忆时不注册写工具，执行时也重新检查配置。

## 设置页编辑

设置 → 记忆提供默认开启的“启用记忆”总开关，持久化到全局 config.json 的 enabled 字段。关闭后，下一次请求不注入记忆、不注册 memory_update，已有文件保留且仍可手动编辑。

设置 → 记忆默认显示“全局记忆”，其他页签使用各个已添加工作空间的名称。
点击内容区进入编辑模式，点击“取消”放弃草稿，点击“保存”将完整 Markdown 文档写入对应记忆文件。
未保存的草稿在切换页签时保留；应用重新获得焦点不会覆盖正在编辑的内容。
保存检查 UTF-8 容量与章节结构，并使用原子写入。若文件在编辑期间被 Agent 或外部应用更新，
保存会拒绝覆盖并保留草稿；取消并重新加载后可以重新编辑。
用户可以修改已停用的记忆；非法配置需先修复才能保存。

返回 Willow、切换页签或点击刷新会重新读取未处于编辑状态的记忆。修改在下一次 Agent 请求开始时生效。
原生打开接口仍可使用系统关联应用打开固定的 `MEMORY.md` 文件。
记忆目录/文件的符号链接及文件硬链接不允许使用，也不会因此扩大普通工具的文件访问权限。
