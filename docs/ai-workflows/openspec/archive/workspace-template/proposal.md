# 提案：添加工作空间时支持选择模板

## 动机

当前用户在创建或添加项目工作空间时，只能初始化一个空的物理目录，或者绑定已有的本地目录。对于特定的垂直场景（例如“金融管理”、“项目管理”等），用户希望能够一键创建包含预置 Skill 和特定业务/应用代码的开发环境。

通过支持选择模板，用户可以在创建工作空间时，自动导入对应的业务模板（Skill 和代码 zip 包），从而快速开展特定领域的工作，提升协作与使用效率。

为了使项目模板能够随应用开箱即用，模板目录应当像 `builtin-skills` 一样打包在应用内部（在开发环境下位于 `app/work/templates`，打包后位于应用资源的 `templates` 目录下），而不是完全依赖用户手动放置在 `userData` 中。

## 目标

1. **模板结构内置化与规范化**：在应用源码包中建立内置的 `templates` 目录。每个模板由元数据 JSON、预览图和 zip 代码包构成，随应用打包分发。
2. **主进程模板读取**：主进程扫描应用包中的 `templates` 目录，读取所有的 `template.json` 并解析元数据，将包括预览图 Base64 在内的数据返回给渲染进程。
3. **拷贝与会话初始化**：创建工作空间时若选择了模板，主进程从内置模板目录中将对应的 zip 包拷贝至新创建的工作空间根目录，并自动初始化工作空间的首个 Chat Session。
4. **指令下发解压**：新工作空间与会话建立后，渲染进程自动跳转至该会话并向 AI 发送默认指令：“解压「<模板名称>.zip」包到当前目录”，由 AI 负责后续的解包和初始化操作。

## 范围

- 规范化应用包内置的模板目录结构。
- 配置 Electron Forge 构建，使 `templates` 目录随包打包。
- 新增获取模板列表的 IPC 接口及控制器。
- 修改 `CREATE_WORKSPACE` 接口，支持接收 `templateId` 参数，在创建工作空间的同时完成内置 zip 拷贝和会话自动创建。
- 升级 `CreateWorkspace.vue` 弹窗，以直观美观的卡片网格形式展示可用模板（包含预览图、名称和描述）。
- 在渲染进程实现创建成功后的自动跳转与消息发送。

## 非范围

- 本次不实现主进程在后台对 zip 文件的直接解压，解压工作由 AI 收到指令后自主执行。
- 不支持动态云端模板库下载，仅支持随包分发的预置内置模板。
- 不影响不选择模板时的普通工作空间创建逻辑。
